# Contributing to Hiptop

Thanks for helping. Hiptop practices what it preaches: a change is ready when its test ran and passed.

## Before you start

- For anything bigger than a small fix, open an issue first so we agree on the approach.
- Read the repository's README for how to build and test it.

## Pull requests

1. Fork, create a branch, and keep the change focused on one thing.
2. Add or update the test that proves the change. A bug fix includes a test that failed before the fix.
3. Run the test suite locally (`uv run pytest` in `hiptop`).
4. Describe what changed, why, and how you verified it.

## Skills and knowledge

- Skills follow the skill contract in `hiptop/docs/`: short, with *When to use*, *Process*, *Red Flags* and *Verification* sections.
- Never commit content you do not have the right to redistribute. Public knowledge enters as download recipes, never as copied pages.
- Never include customer code, logs or names.
